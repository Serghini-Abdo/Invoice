Theme, colours, strings

  • Theme (ui/theme/Theme.kt): Material 3 light scheme from an AppColors object (13 constants: rust primary #B8541A, steel secondary, green, paper background, red, amber). Bundled Cairo font, large type, TouchTarget = 56.dp. No dark theme.
  • Hard-coded colours: AppColors.* or Color.White used directly in 8 UI files. The printed invoice has its own copy in the domain (InvoiceColors).
  • Strings: Kotlin constants in ui/Strings.kt (~240), BackupTexts.kt, Messages.kt; invoice wording in the domain ArabicTerms. strings.xml holds only app_name.

Where RTL, units, TTS, images and export are handled

ConcernPlaces
RTLMainActivity sets the window to RTL; InvoiceTheme forces LayoutDirection.Rtl; LTR islands in Inputs.kt (keypad, number in FieldBox); AutoMirrored arrows; renderer uses RTL text with physical LEFT/RIGHT placement; ItemDescriber inserts an RLM; LayoutAndBackUiTest asserts RTL placement.
Units m/cmLengthUnit, Length (typed value + exact micrometres); ItemEntryForm keeps separate width and height units; ProductDefinition.defaultUnit; UnitToggle in item entry ×2 and product edit; ItemDescriber prints mixed units; Room, backup and drafts store unit per dimension per item.
TTSSpeechController (ar-MA preferred, no speech rate); SpokenText; settings for audio on, item totals, invoice totals; speakers on catalogue cards, confirm total, review total; mute chip; install-voice intent; toast when unavailable.
Image importNone. 16 vector illustrations in domain/catalog/Illustrations.kt; items store only the illustration key.
PDF/PNG exportInvoiceDocumentBuilder → InvoiceLayoutEngine → InvoiceRenderer (PNG 1080 px wide, split above 8,000 px; PDF A4) → InvoiceExporter → share sheet; PdfPrintAdapter. Thumbnail 64 units, tested to stay within 60–80.
BackupOne JSON document, format version 1, max 64 MB; phone keeps 10, Drive keeps 5; validator recomputes every item; staged restore with a safety copy.

Dialogs and empty states

Dialogs: remove item, save invoice, delete invoice, delete product (+ deactivate instead), restore backup, resume draft, leave invoice, two date pickers. Empty states: item list empty, no products, no invoices / no results, invoice not found / unreadable, product not found, export preparing / failed.

Step 3: Findings

A. Existing code that conflicts with the decisions

  1. RTL is forced in two places (MainActivity, InvoiceTheme) and every Row relies on it. Switching to LTR mirrors every row at once.
  2. Arabic alignment in an LTR layout: strings starting with a digit or Latin text, and content-width Texts in a Column, move left. Needs one ArabicText wrapper and an app text field replacing the 9 Material OutlinedTextFields.
  3. AutoMirrored icons: forward arrows must be set explicitly to point right and placed on the right of the label (decided).
  4. Tests assert RTL (LayoutAndBackUiTest): rewrite, plus new checks that a speaker tap never navigates or selects and that every labelled button in the flow has its own speaker target ≥ 48 dp.
  5. Hard-coded colours in 8 UI files and a second palette in the domain (InvoiceColors); launcher icon is rust.
  6. Green meaning clash: unpaid balance must move to ink.
  7. Speaker rule touches most button components in the invoice flow, history and product catalogue: BigButton, SmallAction, ConfirmDialog actions, FormulaOption, date buttons, chips, history cards (Home cards and catalogue cards keep the speaker inside). Best done as one wrapper (SpokenButton: a tile styled like its button + the button, 4 dp gap) so it is the same everywhere. Settings and Backup get none. Some pairs had to be stacked (saved screen bottom, dialogs).
  8. Per-item unit logic: separate width/height units in ItemEntryForm, UnitToggle, ProductDefinition.defaultUnit, drafts, tests. Item storage already fits; an invoice-level unit is new (old mixed invoices: first item's unit, decided).
  9. Room: first real migration (v1 → v2): settings + length unit, label script, speech rate; invoices + length unit; items + image file; products + image file. defaultUnit stays unused.
  10. Backup must carry images: needs a v2 container (proposed ZIP: backup.json + images/), restore accepting v1 JSON and v2 ZIP, staged image swap, validator checking every referenced file, safety copy including images.
  11. Literal image file per item (decided): the file is created at item confirmation and deleted only when its item or invoice is deleted (and restored from backup with it). Editing an old invoice keeps each item's own file.
  12. PNG 8,000 px split is removed; above the limit the app points to PDF (decided).
  13. PDF: pagination exists; new are the page-number footer, the totals colours (deposit green, balance yellow band) and the slim running header on pages 2+ (decided). Thumbnail 64 → 32–40 and InvoiceLayoutTest's 60–80 check change.
  14. Formula text drops "× quantity" because quantity has its own column; Latin labels need LTR isolation, now on printed invoices too.
  15. Unit-label script on re-exports (decided): the setting is read at export time, so an old invoice re-exported after a change shows the new labels (numbers unchanged). Snapshot tests must cover both scripts.
  16. Speak-to-fill (accepted): SpeechRecognizer + RECORD_AUDIO runtime permission, explanation before the system prompt, fallback to typing; offline only with the Arabic pack.
  17. Speech rate not implemented today (setSpeechRate never called).
  18. Existing bug: product "not found" shows "الفاتورة غير موجودة".

B. Affected screens you did not list

Saved and share, invoice detail, catalogue management, product edit, backup, all dialogs, date pickers (flip to LTR), keypad (restyle only), home banners. Treatments are drawn above.

C. Risks

  • Tile next to its button with a 4 dp gap: the two look like one pair, which is the goal, but a thumb aimed at the button edge can hit the tile. The tile only speaks, so a wrong tap is harmless; the tile is never smaller than 48 dp.
  • LTR switch breadth: one wrapper for text and one for buttons, then screenshot checks per screen.
  • Yellow contrast: dark text and a darker edge always.
  • Storage with a file per item: ~40–80 KB per item photo; 1,000 items with photos ≈ 40–80 MB in the app and in every backup (10 on the phone, 5 on Drive). Backups slow down on mobile data.
  • WhatsApp image quality for tall PNGs under the limit: test on the owner's phone.
  • Speech recognition quality for Darija varies by phone.
  • Bidi with Latin labels in RTL text.

D. Open questions

None. All design questions are answered.

E. Calculation stays pluggable

PricingFormula is an enum with when branches in PricingEngine, ItemDescriber, the entry labels, product edit and the backup validator; DB and backups store the formula as a text id. Day 2 adds no new when (formula) branches: formula cell text and the spoken method name come from ItemDescriber only.

F. Kept unchanged

Quantity defaults to 1; repeated products stay separate items; confirming an item returns to the item list; area / perimeter / per-piece maths; immutable snapshots and revisions; no taxes; no other new features.
